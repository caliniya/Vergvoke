## 0. 项目速览

- **是什么**：Vergvoke——Arc 引擎（Anuken/Mindustry 底层，v157.1）+ Java 17 的 RTS+自动化游戏，桌面（SDL）+ Android。极早期，大量 test 占位是正常的。
- **核心架构**：**编译期 ECS**——`annotation` 模块的 ECProcessor 把 `@Component` 组件的字段/方法拍平进生成的实体类（`core/build/generated/.../base/ecs/` 下 `Unit/Building/EntityArs/Systems`），**生成物不可手改**，要改行为去改 ECProcessor 或组件源码。
- **构建**：`./gradlew classes`（验证编译）、`./gradlew dist`（打 fat jar 到 `desktop/build/output/Vergvoke-1.0.jar`，用户直接 `java -jar` 跑这个）。
- **模块**：core（全部游戏逻辑）/ desktop / android / android-old（**别删**）/ tools（Ar/IntAr 等自研容器，命名别改）/ annotation（ECProcessor）。
- **运行数据目录**：`-Dvergvoke.datadir` → `<程序目录>/data` → `%APPDATA%/Vergvoke`。测试存档在 `desktop/build/output/data/map/space.aevs`。

## 1. 本会话的十大主题（改动细节）

### 1.1 索敌组件化（索敌线程退役）

**背景**：原来索敌在 EntityProces（60TPS 独立线程），单位级 `target` 无人写入。
**现状**：
- `TargetComp`（index=4）：字段 `target / angleToTarget / range=400 / retargetInterval=60 / retargetTimer / filter(Boolf<Entity<?,?>>) / @Import x,y,team`；方法 `targetValid(x,y)`、`findTarget(x,y,team)`（复用 `Entities.closestEnemy`）、`updateAngle(x,y)`；**索敌逻辑在 `@Updata update(delta)` 里随主线程实体更新跑**（失效立即重搜 + 按 retargetInterval 周期重搜）
- `WeaponComp`（index=5，原 CombatComp 改名）：`updateWeapons` 开头做武器级锁敌（旋转武器失效/超射程 → `w.type.findTarget`；固定武器 `w.target = target`），随后冷却/转向/开火
- `Turret.update`（建筑）：失效/超射程 → `findTarget(b)` 自取目标
- **EntityProces 现在只剩存档写入状态机**（task/task2/task3），线程保留是因为存档写入还需要它
- 索敌半径：`UnitType.create` 里取武器最大射程写入 `TargetComp.range`

### 1.2 容器迁移（完成）

- `WorldData.units` 字段已删除；`EntityArs.Unit` / `EntityArs.Building`（生成的、static final、带 `e -> e.id` 提取器——ECProcessor 模板 `generateEntityArs` 里改的）是唯一权威容器
- `WorldData.initWorld` 必须做：`EntityArs.Unit.clear()` + `EntityArs.Building.clear()` + `CommandData.init()`（清旧选中）+ `Entities.clearDead()`（清跨局待死队列）
- `moveunits` 是 UnitMath 的寻路队列（**用户计划删掉 UnitMath**，届时一并处理）；`bullets` 是子弹容器（Bullet 不是 @Entity，无生成容器）

### 1.3 建筑生命周期门面（WorldData——全项目唯一写入口）

**API**（WorldData.java）：
- `placeBuilding(Block, tx, ty, angle, team)` → `buildingType.create`（纯构造）→ `placeTiles`（占位瓦片/区块注册 + 覆盖拆除 + 导航 updateBlock）→ `EntityArs.Building.add(b)`
- `placeBuilding(Building b)`（读档路径）→ `placeTiles` → 容器 add（坐标已定，四叉树直接插正确位置）
- `removeBuilding(b)`（幂等，`type == null` = 已回池挡二次销毁）→ 导航清占（`RouteData.updateBlock(b.tx, b.ty)`，**必须在瓦片注销前**，因为 updateBlock(bx,by) 靠 world.getBuilding 找建筑拿占位形状）→ `world.unregisterTiles(b)` → 容器 remove → `Entities.freeID` → `Pools.free`
- `syncTree(b)` = `EntityArs.Building.move(b, b.x, b.y)`——「**改坐标必 move**」铁律的唯一执行点
- `setEnvBlock(x, y, block)`——运行时单格环境方块（瓦片 + 导航）
- `mapLoaded()`——重刷 `RouteData.init()`；**DataIO.read 在瓦片装载完后调用它**（修了「读档后地图固体装饰不进导航图」的 bug：原来 RouteData.init 跑在空世界上）

**职责划线**：World = 纯瓦片层（`registerTile`/`unregisterTiles`，不碰导航/容器）；BuildingType = 纯构造 + 派生数据（`rebuild`）+ `remove` 一行委托门面；RouteData.updateBlock 只许门面调。

**血泪教训（写进门面注释了）**：本会话重构时漏了 `EntityArs.Building.add(b)` → 建筑全消失（不渲染不更新不索敌，只有挡路）；后被编辑器格式化覆盖丢过一次修复，最终补回。

### 1.4 HPA\* 寻路（RouteData 整体重写，~1200 行）

**结构**：
- 地图切 **10 格 chunk**；每对相邻 chunk 的公共边界，每段连续可通行取中点一个「门口」（**密度上限：段数 >2 只留首尾**，钉死碎墙图边数）
- `ChunkNav`（每 chunk 每层一份）：`edges`（门口两两之间的 chunk 内路径缓存，cost=octile 路径长，`minClear`=路径最小 clearance 体积注解）+ `crossings`（本侧入口瓦片）
- **元素惰性创建**：`chunkNav` 数组元素初始 null；`markNavDirty` 对 null 跳过（无缓存无需失效）；`ensureClean` 在 rebuildLock 内创建 + 构建，**换新 ChunkNav 原子换槽**（并发读者持有的旧引用有效）
- `ChunkNav.dirty` 是 **volatile**——重建者最后写 false，读者读到 false 获得 happens-before，JMM 层面覆盖边缓存与 entrances 两路发布（修外部评审的第 3 点）
- 查询 `findPath(sx, sy, tx, ty, unitSize, capability)`：同 chunk 直接 `findPathDirect`（局部 JPS）；跨 chunk 先把起点/终点连到本 chunk 全部门口（`connectFrom`），门口抽象图上 A*（`expand` 按 `minClear > unitSize` 过滤），拼接 `addSeg`（**去重门口接缝重复点**）→ `smoothPath` 收尾
- **跨界记账**：`ANode.viaChunk` 记到达门口时经由的 chunk，换侧扩展补 1 步（自查修过漏设的 bug——编译通过但记账全错）
- JPS 降级为 `findPathDirect`：`searchBounds`（ThreadLocal int[]）限制搜索范围（chunk 内边预计算时传 chunkBounds）

**优化包（全部落地）**：
- sizeMaps 删除（isPassable = `clearanceMap[i] > unitSize` 一个比较）；基础内存 30→15MB/千图
- `updateLock` 换 ReadWriteLock（寻路读/导航更新写）；chunk 重建 rebuildLock + 换新对象
- 寻路 scratch 线程局部（ThreadLocal<Scratch>）：`closedGen/nodeGen` 代际戳（免全量清理）、`nodeIndex`、`live`（Node 池全量归还，修池泄漏）、`openList/openANodes`（PQueue 复用）、`gScore`（**IntFloatMap**，消 Float 装箱）、`aLive`（ANode 池，`obtainANode` 全量赋值 + `freeANodes` 搜索结束归还）
- **clearance = Chebyshev 距离**（8 邻域传播，calcClearanceFull 两遍扫描 + updateRegion BFS 都是 8 邻域）——曼哈顿低估斜角距离会让大单位斜贴穿角；Chebyshev 对方形/圆形碰撞模型都保守。**外部评审建议的 chamfer 3/4 是错的**（那是对圆形的欧氏近似）
- octile 代价（`dist` = max + (√2-1)·min）：g/h/`pathCost`/`AbstractEdge.cost` 全口径一致
- 拆建筑导航清占批量化（一次包围盒泛洪，原来逐格）；小图（≤30 万瓦片 = FULL_RECALC_MAX_TILES）导航更新直接全量重算（精确），大图有界泛洪（±24，已知近似：放墙后距离可能低估=过度封锁，拆墙后高估=保守绕路）

**已知取舍**：h 对门口 A/B 侧 ≤1 偏差（近似最优）；entrances map 只增不清（无害垃圾）；大图泛洪近似；读锁下可读到写者半更新的距离场（int/boolean 写原子，游戏可容忍）。

**外部评审复核结论**（另一 AI 的四点意见）：
1. 「JPS 对 unitSize>0 不保证正确」——**不成立**（膨胀图仍是逐格谓词均匀网格，JPS 完备最优；参考 Rabin JPS+ with clearance）
2. 「4 连通 clearance 斜角穿角」——**成立已修**（Chebyshev；评审的 chamfer 建议是错的）
3. 「entrances 发布无 HB」——**理论成立已修**（volatile dirty；评审只看到 entrances、漏了边缓存内容同样裸）
4. 「拼接重复点」——**成立已修**（addSeg）

### 1.5 生命周期 / 重载修复

- **重载线程泄漏**（子弹渲染错乱的根源）：`ThreadedStop` 事件在 System.init 里注册（`stopThread`：threadRunning=false + interrupt + join(100)，**幂等**）但**从未被触发** → 每次重载旧 BulletProcess/UnitMath/EntityProces 线程泄漏并与新实例双跑——旧子弹线程把上一帧陈旧缓冲换进 `WorldData.bullets`（它是「交换引用」式双缓冲）
- 修在 `Data.loadSystems`：`Events.fire(ThreadedStop)` → `Systems.systems.clear()`（旧主线程系统实例不清理会被 updateAll 双驱动）→ 创建新实例 → `WorldData.rebuildTransientContainers()`（重建 moveunits/bullets + `Entities.clearDead()` + `initAllTrees` 重刷四叉树，含把读档实体按最终坐标重插）
- `System` 停机日志已静默（interrupt 落在 tick sleep 是正常停机路径，不再打堆栈；`thread stopped: X` 确认日志保留）
- 每次重载残留 3 个死系统的事件监听器（无害，`stopThread` 幂等）；旧 MapRender 区块纹理未 dispose（GPU 内存每次重载漏一点，**未修**，见待办）

### 1.6 帧时间 / 焦点暂停

- **巨帧 delta 钳制**：`Vergvoke.init` 里 `Time.setDeltaProvider(() -> Math.min(graphics.getDeltaTime() * 60f, 10f))`——不钳制则 Win+Shift+S 截图/焦点切换/卡顿后的巨帧把移动中的单位一帧甩出地图（然后 UnitMath 把他们「从地图外面走回来」——用户实际观察到并报告的现象）。主循环是唯一 delta 消费点（其余全是参数传递）
- **焦点暂停**：`Game.focusPaused`（Vergvoke.pause/resume 维护）→ `Game.update` 门禁（主线程模拟冻结）；背景线程由 System 基类监听 GamePause 自动挂起（**isPausable 的才挂起**）；渲染/UI 不冻结（可截图）。InputProcess 原本就在焦点暂停时屏蔽相机输入

### 1.9 ECProcessor 增强（annotation 模块，ECProcessor.java）

- **组件方法全量注入**：`injectComponentHelpers` 不再只挑 public——private/protected/包私有/static 辅助方法都铺进生成实体并**保留原修饰符**（原来强制 PUBLIC、跳过 static）；与 Entity 基类同签名的方法直接报错并提示用 `@OverrideEntity`
- **@Import 可借基类字段**：解析顺序 = 其他组件注入字段 → `findBaseField`（Entity 基类同名字段，擦除后类型比对）；都没有才报错。组件里引用 x/y/team 等基类字段写 `@Import` 声明即可（以前靠同名字段占位去重）
- **字段初始化表达式跟到生成实体**：`initializerOf`（VariableTree.getInitializer）+ FieldSpec.initializer——`public float speed = 5f` 现在会正确出现在生成类里。**但对象池复用不走字段初始化**：Pools.obtain 的旧实例只有构造时初始化过，复用前必须 reset/create 显式赋值
- 组件 import 原样搬进生成文件（既有行为）——方法体里可直接用 Mathf/Entities 等短名

## 2. 关键数据流（文字版）

**主循环**（Vergvoke.update）：`super.update()`（Time.update → delta，已钳制 ≤10 帧）→ `platformInput.update` → `Game.update(delta)`（门禁：inGame && !focusPaused）→ `Systems.updateAll(delta)`（**帧序**：Building/Unit sync → 组件系统 → Building/Unit update——GameProcess/Render 挂在 Systems.systems 里被一起驱动）→ `Render.it.update` → UI → DebugRender

**寻路查询**（UnitMath 60TPS 线程，读锁内）：`findPath` → 同 chunk？→ `findPathDirect`（局部 JPS，scratch 复用） ：→ `connectFrom`×2（ensureClean 惰性建 chunkNav + 局部 JPS 连门口）→ 门口抽象图 A*（`ensureClean` 两侧 + `expand` 按 viaChunk 记跨界账）→ 拼接 addSeg → smoothPath

**建筑放置**（任意调用方）：`WorldData.placeBuilding(...)` → BuildingType.create（纯构造 + 池 + 全字段赋值）→ placeTiles（逐占位瓦片：覆盖拆除[递归走 removeBuilding] → world.registerTile → RouteData.updateBlock）→ 容器 add（树插正确位置）→ updateBlock 内部 markNavDirty（±30 范围 chunk 标脏，惰性重建）

**建筑销毁**：GameProcess 判死 → `e.kill()` → BuildingType.remove → `WorldData.removeBuilding`（导航清占 → 瓦片注销 → 容器 → ID → 回池）；伤害路径：applyDamage（可能 BulletProcess 线程）→ `Entities.markDead` 登记（wasAlive 去重）→ GameProcess 开头 `drainDead` → kill（**销毁只在主线程**）

## 3. 组件速查（UnitDef / BuildingDef）

| 实体 | 组件（index） | 备注 |
|---|---|---|
| UnitDef → base.ecs.Unit | State(1)、Move(2)、Target(4)、Weapon(5) | StateComp：isSelected + @Write/@Read（含 team 序列化）；MoveComp：speed/speedt/speedX/speedY/angle/targetX/targetY(@Save1/2)/x/y(@Save3/4)/arriveRange/moving/pathed/velocityDirty/path/pathIndex；TargetComp：见 1.1 |
| BuildingDef → base.ecs.Building | Block(3)、Target(4)、Turret(6) | BlockComp：block 引用/tx/ty/angle/tileSize/shapeOffsets + getOccupiedCoords/occupies + @OverrideEntity contains/hitbox；TurretComp：self/reload + @Import target/rotation/x/y + reloadTime/rotateSpeed/bullet |

**ECProcessor 关键规则**：组件字段初始化表达式会跟到实体（但池化复用不走初始化）；@Import 借其他组件或基类字段（不能与 @Save 同字段）；@Save 只支持基本类型+String；同组件 @Save 与 @Write/@Read 互斥；与基类同签名的普通方法报错（用 @OverrideEntity）；组件方法全量注入且保留修饰符。
