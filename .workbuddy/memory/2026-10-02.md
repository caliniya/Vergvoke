# 2026-10-02

## 修「击杀即崩」：`Entity.kill` 的 NPE

用户第一次真正跑起来 jar（`desktop\build\output\Vergvoke-1.0.jar`），开局就崩：

```
at caliniya.vergvoke.base.game.Entity.kill(Entity.java:132)      ← type.kill(this)，type 为 null
at caliniya.vergvoke.system.game.GameProcess.update(GameProcess.java:37)
```

### 根因：后台线程在销毁实体

`Entity.applyDamage` 血量归零直接 `kill()` → `remove()` → `Pools.free` → `reset()` 置空 `type`。
而伤害结算是 **BulletProcess 线程** 发起的（`b.type.hit` → `e.hit` → `applyDamage`），
同一处紧接着又把 `e` 塞进 `freshKills`，主线程下一帧 `e.kill()` 对着 `type == null` 的对象干活 → NPE。

### 定案：销毁只在主线程

- `Entity.applyDamage` 血量归零**不再直接 kill**，改为 `Entities.markDead(this)`；
  用 `wasAlive`（扣血前 health > 0）去重，血已归零后再挨打不重复入队。
- `Entities` 新增静态 `pendingKills` + `KILL_LOCK`：`markDead` / `drainDead` / `clearDead`。
- `GameProcess.update` 开头 `Entities.drainDead(freshKilled)` → 逐个 `kill()`，**唯一销毁出口**。
- `BulletProcess` 的 `freshKills` / `KILL_LOCK` / `drainFreshKills` 全部删除（与 markDead 重复）。
- `Entity.draw/remove/kill` 三个入口一律加 `type == null` 提前 return 的安全网
  （已回池的对象还可能躺在某张列表里被摸到，尤其渲染线程）。
- `WorldData.initWorld` 里加 `Entities.clearDead()`，防止跨局残留把已回池的对象再杀一次。

### 教训

- 之前记的「`remove` 会被后台线程直接触发，要加锁」是**治标**：后台线程根本不该碰对象池。
  容器 / ID / 池三条链路都必须主线程独占，后台线程只做登记。
- `Pools.free` → `reset()` 置空 `type` 是「已回池」的唯一可靠标志，所有跨帧持有的引用都得靠它兜底。

## 修「有些敌对建筑不去打」（索敌）

两个原因叠加：

1. **读档后建筑没同步四叉树节点（主因）**。
   `DataIO` 建建筑的路径是 `buildingType.create(team,0,0,0)`（那时按 (0,0) 插进
   `EntityArs.Building` 的树）→ `read` 恢复真实 tx/ty → `rebuild` 重算 x/y → `setBuilding`。
   单位路径有 `EntityArs.Unit.move(u, u.x, u.y)`，**建筑这边漏了**。
   结果：所有读档进来的建筑在树里都停在左上角 (0,0) 附近，索敌查询在别处永远查不到它们
   ——但渲染/更新走 array、瓦片层走 WorldChunk，全都正常，所以现象是"有些建筑没人打"。
   修在 `BuildingType.rebuild` 末尾统一 `EntityArs.Building.move(b, b.x, b.y)`。
   **铁律：改了实体坐标或 size，必须同步四叉树节点（move）。**

2. **射程判定只算到目标中心**。3×3 建筑半边长 48px，且旋转武器是按挂载点 `wx/wy`
   （`WeaponType.x/y` 偏移，测试单位就是 50）算射程的，两层一叠加就出现
   "单位明明站在射程内、武器却判定够不着 → 把 target 丢掉"。
   新增 `Entity.dst2Surface(px,py)`（点到包围盒的最短距离平方，盒子内为 0），
   `Entities.nearbyEnemies/closestEnemy` 加 `byEdge` 尾参：
   **索敌类（TargetComp.targetValid/findTarget、WeaponType.findTarget、WeaponComp 超射程判定）
   传 true；子弹命中传 false**（不然子弹会在离建筑老远就炸）。
   顺带修 `Weapon.update` 的 `target.health < 0f` → `<= 0f`（血量归零被 clamp 成 0，
   写 `< 0` 等于永不成立，会朝已死目标继续开火）。

## 阵营名显示（head-up team tag）

- `TeamTypes.localizedName()`：**方法不是 final 字段**。枚举在游戏很早就会被触碰，
  `Core.bundle` 要等 `Init` 走一半才建好；`DamageType` 那种 `final` 写法只是碰巧没踩雷。
- 键 `team.Xxx`，两份语言文件都加了（zh 暂用英文原名，派系设定还没定）。
- 绘制统一走 `UnitRender.drawTeamTag(Entity, topY)`，`UnitRender.showTeam` 开关默认开；
  `BlockRender` 调它（同包，且本来就在复用 `UnitRender.debug`）。
- Arc 的 `Font.draw` **没有** `(str, x, y, align, wrap)` 重载，只有 `(str, x, y, align)`
  和 `(str, x, y, targetWidth, align, wrap)`——抄 Mindustry 写法时要留意。
- 世界空间画字沿用项目既有风格：直接 `Fonts.outline.draw(...)`，不额外 setScale。
