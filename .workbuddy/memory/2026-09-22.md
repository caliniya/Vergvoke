### ⚠️ 本轮发现的严重问题（都在这两天的重构里）

**A. `UnitType.create(team, x, y)` 三个参数全部没用上。**
通读 `UnitType.java:100-133`，方法体里没有任何 `u.team =` / `u.x =` / `u.y =`。
（历史对比：这三个字段原先由被删掉的生成工厂 `Unit.create(team,type,x,y)` 赋值，删工厂时漏了。）
→ 现在所有单位都生成在 (0,0)、`team` 为 null。

**B. 单位注册进了错的集合。**
`EntityArs.Unit` 与 `WorldData.units` 是**两个不同的 `EntityAr` 实例**：
- `EntityArs.Unit` —— 只被生成的 `Systems.updateAll` 遍历（sync + update）
- `WorldData.units` —— 被 `GameProcess`(死亡判定/武器/四叉树移动)、`UnitRender`(渲染)、
  `EntityProces`(战斗索敌)、`TeamData`、`Entities.nearbyEnemies`、`CommandInfoWindow`、`DebugFragment` 使用
新加的 `EntityArs.Unit.add(u)` 只进了前者，所以单位会被逻辑更新但**不渲染 / 不可选中 / 不索敌 / 不判死**。
更根本地：**全项目没有任何地方把 Unit 加进 `WorldData.units`**，唯一入口 `Entities.add(Unit...)` 零调用点
（只有 Building 走 `World.java:95,114 → Entities.add`）。这是昨天之前就存在的洞，今天只是新加了一个旁路。
修法二选一：create 里改调 `Entities.add(u)`（顺带解决 id），或让 `WorldData.units` 直接复用 `EntityArs.Unit`
（注意后者构造时没有 id 提取器 `unit -> unit.id`，需要一起改）。

**C. Unit 没有 id。** `Entities.assignID()` 只在 `Building.java:241` 调用过，Unit 全程 id=0。
