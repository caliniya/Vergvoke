## 第四次（22:24）· 排查 `Game.starMap` 空指针崩溃

### 崩溃

```
NullPointerException: Cannot read field "w" because "caliniya.vergvoke.game.Game.starMap" is null
  at Render.clampCamera(Render.java:216)
  at Render.update(Render.java:181)
  at Vergvoke.update(Vergvoke.java:94)
```

### 根因（已确认，行号与当前源码完全吻合）

`clampCamera()`（Render.java:206-218）只判了 `WorldData.world == null`，**没判 `Game.starMap == null`**，
却在 216/217 行直接用 `Game.starMap.w/h`。

为什么会同时出现「world 非空 + starMap 为空」：

- `Game.starMap` 全项目**只有一处赋值**：`Data.enter()` → `Data.java:76` `new StarMap(2000,2000)`。
- `Data.enter()` 全项目**只有一个调用点**：`DataIO.java:104`，而且被 `Core.app.post(...)` 推到**下一帧**主线程执行。
- 但 `WorldData.initWorld(...)` 在 `DataIO.java:97` 就**同步在主线程**执行了。
  → world 就绪 与 starMap 就绪 之间隔着「IO 线程 read + 一帧 post」，主循环照跑 → 崩。
- `MenuFragment` 的 test2 按钮（62-63 行）只调 `WorldData.initWorld` + `Data.loadSystems`，
  **根本不调 `Data.enter()`** → starMap 永远为 null，一进 test2 就崩。

`Render.it` 和 `universeCamera` 之所以非空（所以报错才是 starMap 而不是它们）：
`Init.java:125-126` 在启动阶段就 `Render.it = new Render(); Render.it.init();`。

### 为什么是现在才崩（关键）

21:51 的提交 4556d3b 把 `Render.updateAll(delta)` **删除**，逻辑并进了实例方法 `Render.update(delta)`，
`Vergvoke.java:94` 相应从 `Render.updateAll(delta)` 改成 `Render.it.update(delta)`。
旧的 `updateAll` 只遍历子渲染器 + flush，**从不碰相机、不调 clampCamera**；
改完之后相机逻辑（含 clampCamera）变成**每帧无条件执行**，连主菜单里也跑。
菜单阶段靠 `WorldData.world == null` 侥幸提前 return，一旦 world 被 initWorld 赋值就炸。

### 修法（三选一，推荐 1+2）

1. `clampCamera()` 加 `if (Game.starMap == null) return;`（或只对星图那两行单独判空）。
2. `Vergvoke.update()` 里 `Render.it.update(delta)` 用 `Game.inGame`（或 `WorldData.world != null`）门控——
   相机 clamp 本来只在游戏内有意义。
3. 把 `DataIO.load` 里的 `WorldData.initWorld(...)` 也挪进 `Core.app.post`，让 world 与 starMap 同一帧就绪。
