### 根因定位（ECProcessor 校验点）

| 报错 | 校验位置 | 规则 |
|---|---|---|
| Duplicate entity field 'target' | `ECProcessor.java:631-642` | 同一实体内组件字段名不能重复（`injectedFields.putIfAbsent`）；与 Entity 基类同名的字段会被跳过不注入（627 行） |
| @Updata ... named 'delta' | `ECProcessor.java:709-723` | `@Updata` 方法有且只有一个形参，类型 float，**名字必须等于 `DELTA_NAME`="delta"**（81 行定义） |
| Duplicate @Component.index | `ECProcessor.java:752-770` | 同一实体内 `@Component.index` 不能撞（决定序列化顺序，撞了顺序未定义） |

补充：`validateComponentIndexes`（116 行起）**只要求 index != 0**，不要求全局唯一，
所以给 TargetComp 换个没被占的 index（现有 State=1 / Move=2 / Combat=5）是自由的。

### 失败如何扩散

`planEntity` 出错 → 782 行 `if (!valid) return null`
→ `process()` 126 行 `continue`，Unit 的计划不进 `plans`
→ `generateEntity` 不执行，**Unit.java 不生成**；`generateEntityArs(plans)` 拿到空 plans，**EntityArs.java 也不生成**
→ 所有引用 `Unit` 的类（UnitType / Weapon / Entities / Data / Render…）报"找不到符号"

生成目录实测只剩 `Systems.java`（1280B）—— `generateSystems` 无条件生成，
但里面照样写着 `for (Unit e : EntityArs.Unit)`，所以它自身也是红的。

注：ECProcessor 有容错设计（108-110 行注释、`usesBrokenComponent` 跳过坏组件），
但那是**组件级**错误的兜底；这三条都是**实体级**错误，直接丢掉整个实体计划，没有兜底。
