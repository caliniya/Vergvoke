# 索敌组件参数扩充 + 默认索敌逻辑实现

## 背景（已确认的现状）
- `TargetComp` 只有 `target`/`angleToTarget` 两个字段，**全项目无人写入**；旋转武器已通过 `WeaponType.findTarget` 自行索敌，但固定武器依赖的单位级 `u.target` 永远为 null，`angleToTarget`（固定武器 shootCone 开火判定用，`Weapon.java:91` 读取）也恒为 0。
- 单位级索敌的正确驱动位置是 `EntityProces`（60TPS 索敌线程），符合 javadoc「索敌在 EntityProces 写、开火在主线程」的分工。
- ECProcessor 会把组件 import 原样搬进生成文件（ECProcessor.java:1015），组件方法体可直接用 `Mathf`/`Entities` 等短名。

## 一、TargetComp 参数与方法（`type\def\comps\TargetComp.java`）

新增字段：
- `float range = 400f` — 索敌半径（与 WeaponType.range 默认一致）
- `float retargetInterval = 60f` — 周期性重搜间隔（tick，60TPS 下约 1 秒一次），保证「最近目标」能追踪；目标失效时无论如何立即重搜
- `float retargetTimer` — 内部计时
- `Boolf<Entity> filter = null` — 可选目标过滤器（null=不过滤），复用 `Entities.closestEnemy` 现成的带 filter 重载

新增方法（`@Updata update` 保持空，索敌由 EntityProces 驱动，不放主线程 update）：
- `boolean targetValid(float x, float y)` — `target != null && target.health > 0 && dst2 <= range²`（与 EntityProces 现有校验范式一致）
- `void findTarget(float x, float y, TeamTypes team)` — `team == null` 直接返回；先置 `target = null`；filter 非空走带过滤的 `closestEnemy` 回调赋值，否则 `target = Entities.closestEnemy(team, x, y, range)`
- `void updateAngle(float x, float y)` — target 非空时刷新 `angleToTarget = Angles.angle(x, y, target.x, target.y)`

## 二、EntityProces 接线（`system\world\EntityProces.java`）

在单位循环的武器循环之前插入：
```java
u.retargetTimer -= delta;
if (!u.targetValid(u.x, u.y) || (u.retargetInterval > 0f && u.retargetTimer <= 0f)) {
    if (u.retargetInterval > 0f) u.retargetTimer = u.retargetInterval;
    u.findTarget(u.x, u.y, u.team);
}
u.updateAngle(u.x, u.y);
```
固定武器 `w.target = u.target` 的赋值已有，无需改；`angleToTarget` 刷新后固定武器的 shootCone 开火判定即生效。

线程安全：EntityProces 写 `target`、主线程读，与现有 `w.target`/`building.target` 同模式（health 已 volatile），不新增同步。
