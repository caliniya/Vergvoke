# 配方组(Recipe/RecipeStack)实施计划

## 架构(已与用户对齐)

```
Recipe(content 侧配方描述)      time + consumers[] + outputers[],canCraft/craft 两阶段编排
RecipeStack(实体侧配方组)       recipes[] + current 下标 + progress;select() 切换清进度
CraftComp(薄驱动)               stack.current() → 推进度 → canCraft? craft : 钳住
Factory                         Ar<Recipe> recipes(content 声明,共享模板)
```

## 改动清单

1. **两端补检查方法**(原子性前提):
    - `Consumer`:加 `public boolean canCons() { return true; }`(基类默认可)
    - `ItemConsumer`:覆写 `canCons()` = `module != null && module.getAmount(cons.type) >= cons.amount`
    - `Outputer`:加 `public boolean canOutput() { return true; }`
    - `ItemOutputer`:覆写 `canOutput()` =
      `module != null && module.accepts(output.type) && module.capacity - module.getAmount(output.type) >= output.amount`
2. **Recipe 补全**:`time`、`consumers`/`outputers` 集合、链式 `time()/cons()/output()`、`canCraft()`(全端校验,任一失败
   false)、`craft()`(先全部 cons() 再全部 output())
3. **RecipeStack 实现**:`recipes`(Ar<Recipe>)、`current`(int,-1 停工)、`current()` 取当前、`select(int)` 切换并清
   `progress`;`progress` 字段放 RecipeStack(@Save 挪到这里,CraftComp 的 @Save progress 移除)
4. **CraftComp**:字段改为 `RecipeStack stack`;update 用上面骨架;删掉不再用的字段
5. **Factory**:`outputItem/outputAmount/craftTime` 平铺字段改为 `public Ar<Recipe> recipes = new Ar<>()`(content
   声明共享模板)
6. **BuildingType.create**:`instanceof Factory f` 分支重写——`b.stack = f.recipes` 的深拷贝装配(每条 Recipe 拷贝端对象并
   bind 实体模块;需确认深拷贝策略:端对象加 `copy()` 方法,参照 Ability.copy() 先例);复位 progress → stack 重置
7. **Blocks.java**:factory 的配方改为 Recipe 声明式(
   `new Recipe().time(60).output(new ItemOutputer().output(new Item(Items.Ge, 1)))` 形态)
8. **DebugWindow**:「切换工厂配方」测试项(循环 select + Log 打印当前配方)
9. **编译验证**(`./gradlew classes`,核对生成 Building 的字段变化)+ main.txt 同步(CraftComp/Factory/配方描述,SAVE_VERSION
   视 @Save 变化决定是否 bump——progress 从 CraftComp @Save 挪走会改布局,当前版本号已是 1,与用户对齐后处理)

## 已知取舍

- 深拷贝实现按"端对象 copy()"最简做法(字段少,手写 clone 即可)
- 配方切换 UI 入口本期只有 Debug 项
- 多输入多输出配方的 canCraft 顺序:先全部校验再全部结算,不做部分回滚
