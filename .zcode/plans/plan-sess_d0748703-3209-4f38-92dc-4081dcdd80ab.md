# 工厂(第一座生产建筑)实施计划

## 设计概要

```
Factory (world/blocks/production/, extends Block)  ← 配置载体:craftTime/outputItem/outputAmount
   └─ BuildingType.create 里 instanceof Factory 拷配方进实体 + 复位 progress
CraftComp (type/def/comps/, @Component index=8, proc="main")  ← 通用生产逻辑
   └─ @Updata: progress += delta → 到点且仓库有位 → item.addItem(产出);满仓则 progress 钳住等待
   └─ @Import item(借 Entity 模块);@Save progress(存档续产)
```

行为全部走既有通道:GameProcess 的 `b.update`(拍平)+ `b.type.update` 钩子都不用动;ItemModule 容量/accepts/序列化现成。

## 改动清单

1. **`world/blocks/production/Factory.java`(新)**:extends Block。字段 `craftTime`(默认 60,即 1 秒)、`outputItem`、
   `outputAmount=1`;`load()` 里 `region = Core.atlas.find(name, "white")`。参照 Turret 的"配置+load"模式,不覆写 update。

2. **`type/def/comps/CraftComp.java`(新)**:`@Component(name="Craft", index=8, proc="main")`。
    - 实例字段:`craftTime`、`outputItem`、`outputAmount`(create 灌入)、`progress`(运行态,`@Save(index=1)` 持久化)
    - `@Import item`(ItemModule,借 Entity 基类)
    - `@Updata update`:outputItem 为 null 直接 return(非工厂建筑无害);`progress += delta`,到 `craftTime` 且
      `item.accepts(outputItem)` 则 `addItem` 并 `progress -= craftTime`;仓库满则 progress 钳在 craftTime 等待(
      经典Mindustry 行为)。第一期不做输入消耗(逻辑结构留好)。

3. **`UnitDef`/`BuildingDef`**:BuildingDef comps 加 CraftComp(仅建筑)。

4. **`BuildingType.create`**:加 `if (block instanceof Factory f)` 分支——拷 craftTime/outputItem/outputAmount、
   `progress = 0`(对象池复位,参照 Turret 拷贝块 :89-95 的写法)。

5. **`content/Blocks.java`**:注册 `factory`(size=2,buildable),加进内容加载。

6. **`GameIO.SAVE_VERSION` 3→4**:Building 序列化新增 CraftComp 的 @Save 字段,写入布局变化,旧档拒载。

7. **DebugWindow 验证项**:
    - "生成工厂(镜头中心)":`WorldData.placeBuilding(Blocks.factory, 格坐标, 0, Game.team)`(参照"生成敌方炮塔"项)
    - "打印建筑库存":遍历/找镜头附近建筑,Log 输出 `item.getAmount(Ge)` 与 progress,验证生产循环

8. **`./gradlew classes` 验证** + main.txt 同步(组件 index 表加 Craft=8、BuildingDef 组合、Blocks
   内容描述、SAVE_VERSION=4)。

## 已知取舍

- 产出堆积在工厂自身 ItemModule(容量默认 100),无物流;满了停产。
- 无输入消耗:CraftComp 结构留好 inputs 的位置,第一期配方无输入。
- 工厂贴图先用 atlas 兜底("white"),正式贴图后续补。
- 不做建造菜单/点击面板,放置走调试窗与读档。
